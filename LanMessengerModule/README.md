# 局域网通讯（安全传输开发版）

仅用于可信局域网，不要将端口暴露到公网。当前源码中的消息和文件连接已使用 TLS 1.3，首次连接需要双方核对校验值并确认；UDP 发现仍是未认证的在线提示，设备名称和 IP 不能作为身份凭据。没有明文兼容或降级，两端均需使用安全传输版本。

### 开发状态与安全边界

`security` 包提供 AES-GCM 存储、系统密钥库适配（macOS Keychain / Windows DPAPI / Linux libsecret）、持久设备证书和加密信任记录。打开插件时在后台初始化密钥及加密历史，失败则阻止访问历史和启动服务，不回退到明文。当前源码已接入聊天记录、联系人、配置及粘贴截图缓存加密；用户选择保存的接收文件、接收临时文件和导出图片仍是普通文件。

设备身份初始化状态写入必需的加密清单；证书丢失、损坏、身份不匹配时拒绝自动换钥。初始化中途崩溃可能需要显式恢复，不会把错误当作首次使用。只有双方确认当前连接的校验值后才放行消息和文件；关闭弹框、拒绝、断开或超时都会取消本次配对。撤销信任会关闭对应连接并取消相关传输；设备密钥变化需显式撤销旧信任后重新核对。

自动测试使用临时文件、回环网络和模拟的操作系统凭据接口；打包检查会加载 JNA 原生桥，但不访问真实系统密钥库。仍需完成真实系统密钥库及跨平台双机验证；尚未替换已安装插件。用户已确认没有旧记录，本版本不提供旧数据迁移，也不读取、修改或删除宿主共享数据库及旧明文缓存。

控制器使用独立加密历史后端 `ChatRepository(Path, LocalVault)`，加密正文、状态、错误、附件名/路径、设置值和联系人详情，没有明文搜索列。搜索在后台按批解密匹配，支持中文、字面量 `%`/`_` 和分页；可通过工作线程中断取消。数据库仍暴露记录 ID、联系人 ID、顺序、联系人更新时间和密文长度等元数据，并不隐藏记录数量或关系。密文绑定数据库绝对路径及记录身份，不能直接移动数据库文件到新路径使用。已有加密数据库或缓存但密钥清单缺失时拒绝初始化，不自动生成替换密钥。

## 使用

1. 两端选择实际局域网网卡并填写设备名称，启动服务。默认发现端口为 UDP `2425`，消息和文件共用 TCP `2426`。
2. 点击“刷新发现”，或通过“手动连接”填写对方 IP 和 TCP 端口。发现端口必须一致；广播被网络隔离时可尝试手动连接，不扫描网段。
3. 对发现的联系人右键选择连接/验证，或使用手动连接。首次连接时双方通过可信渠道核对弹框中的完整校验值，确认相同后各自点击信任；不是仅核对设备名称。配对总期限为 120 秒，单方确认不会放行。已信任设备重连无需再次弹框，可通过联系人右键撤销信任。
4. 连接验证通过后选择联系人发送文字；Enter 发送，Shift+Enter 换行。“已送达”表示对方已保存，不代表已读。失败消息可重新发送。
5. 可多选或拖入多个文件，也可粘贴剪贴板图片；图片发送前会确认。接收方必须选择保存位置或拒绝，不自动接收或执行文件。
6. 图片接收完成后直接显示缩略图，点击“查看图片”缩放或另存。文件卡片显示进度、速度、取消及失败原因。失败重试从头开始，不支持断点续传；令牌已用或服务重启时需要发送方重新发送。
7. 会话支持搜索、复制、较早记录和最新消息；只有停留在列表底部时才自动跟随新消息。停止服务后可清空历史，用户原文件和接收文件不会删除。

## 限制与存储

- 文本最大 1 MiB；单文件最大 1 GiB；每批最多 64 个文件，最多 2 个同时进行的上传/接收任务。接收队列有上限；发送方忙时显示失败，可稍后重试。
- 网络连接超时 5 秒，读取超时 15 秒，单连接绝对上限 10 分钟（也约束阻塞写入）。超慢文件超过上限需重新发送。
- PNG/JPEG/GIF 静态预览，最高 2500 万像素；缩略图最多缓存 64 张，预览解码最大边长 2048，不自动解码完整超大图。
- 配置、联系人及聊天记录保存在独立的 `~/.opencgl/lan-messenger/secure-history.db`；安全清单和设备资料位于同目录的 `security/`，不访问宿主共享数据库。
- 粘贴截图编码为 PNG，编码后最大 16 MiB，密文保存在 `~/.opencgl/lan-messenger/encrypted-images/UUID.sealed`。预览、发送和重试在内存中解密，不生成明文预览临时文件；另存图片需用户明确选择目标。停止服务后可点“清理截图缓存”，只删除本插件生成的常规 UUID 密文文件，不跟随符号链接；历史中相应预览会显示不可用。清理历史本身不删除截图缓存。缓存文件数量和密文长度仍可见。
- 接收文件先写目标目录临时文件，长度和 SHA-256 校验通过后才提交。覆盖现有文件需确认；失败或取消不会把部分文件当作成功文件。
- 重启后未完成消息/文件显示中断。联系人保留，在线状态等待新的发现或握手更新。

## 构建与产物检查

使用 Zulu JDK 21 执行 `mvn -pl LanMessengerModule clean verify`。产物为 `LanMessengerModule/target/LanMessengerModule-1.0.0.jar`，内含 JNA 及 jna-platform 运行依赖，保留插件版本信息；宿主 API、基础组件、JavaFX 和测试依赖不重复打入。

`verify` 在打包后执行 `PackagedPluginIT`，使用隔离类加载器验证实际 JAR 的 JNA 加载、平台二进制资源、中文加密往返及版本信息。普通 `test` 只执行功能测试，普通 `package` 不执行这项产物检查。可通过 Maven 的 `-Djvm=/path/to/runtime/bin/java` 指定测试 JVM，检查主程序精简运行时；这不等同于完整桌面应用或 Windows/Linux 双机验收。

## Windows 排查与验收

自动测试使用临时数据库和本机回环，没有修改防火墙或广播到真实局域网。当前开发验证环境为 macOS；**尚未完成 Windows 与 macOS 双机实测**。

Windows 需允许该应用在可信“专用网络”接收所配置的 UDP/TCP 端口。检查选中的网卡不是 VPN、虚拟机或回环网卡；如果发现不到但手动连接成功，通常需要检查广播隔离。不要为此关闭整个防火墙。

双机验收清单：相互发现 → 手动连接 → 中文多行消息 → 重启历史 → 图片粘贴/预览 → 多文件 → 拒收/取消 → 端口占用回滚。两个不同设备应使用独立配置目录，不要复制设备 UUID。
